# crowd-join-kit

1500 个人逐个进房间，进一个发一拍。每一拍**只发新来的那一个**（增量），
不把已经在场的人重发一遍。

## 问题

人一个一个进房间，如果每一拍都把已经在场的人全部重发一遍，第 k 拍就要发
k 个人，1500 拍合计是三角数：

```
1 + 2 + ... + 1500 = 1 125 750 人次  ≈ 24 000 000 字节 / 秒级耗时
```

人越多，后面每一拍越大 —— 这就是「每一拍都太重」的来历。

## 做法

`src/CrowdRoom.ts`：人进场时把新人放进 `state.people`，立刻
`broadcastPatch()` 发一拍。框架的增量序列化只把**这一拍的变化**（新来的
那一个人）编码进包，已经在场的人不进包、也不动。对面（客户端）把每一拍
增量应用到本地状态上，画布上的点跟着一个一个多起来。

进场规则（`personAt(i)`）：第 i 个人横坐标 `120 + (i % 50)`（120..169
循环），纵坐标 80，分数 7。第一个在 (120, 80)，最后一个（i=1499）在
(169, 80)。

不定 `patchRate`：定时器会把先后进场的几个人合并进一拍，对面就不是一个
一个看到人出现了。

## 量法

```
pnpm bench             # delta 模式：每一拍只发新来的那一个
pnpm bench -- --full   # full 模式：每一拍重发全场（反例对照）
```

两种模式量同一串东西：1500 拍的发送耗时、增量字节合计、对面解出来的人数
和坐标。典型结果（本机）：

| 模式 | 拍数 | 发送耗时 | 增量合计 | 对面人数 |
|------|------|----------|----------|----------|
| delta | 1500 | ~75 ms   | ~36 500 字节 | 1500 |
| full  | 1500 | ~1000 ms | ~24 000 000 字节 | 1500 |

## 约束测试

```
pnpm test
```

`test/crowd-join.test.ts` 断言：1500 拍、一串发完 < 180 毫秒、增量合计
< 400 000 字节、每一拍只装得下一个人、对面人数一个一个涨到 1500、第一个
人 (120, 80) 分数 7、最后一个 (169, 80) 分数 7、中间每个人按
`120 + (i % 50)` 一个不少。
